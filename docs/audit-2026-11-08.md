# Audit Aplikasi PSB Fathan Mubina

**Tanggal:** 8 November 2026

**Commit yang diperiksa:** `e7a52f4dbf12254432b9d3a8aedc3deaef992711`

**Cakupan:** frontend PWA, bridge, backend Google Apps Script, alur transaksi, keamanan, workflow CI, dan tampilan publik.

## Ringkasan

Audit source menemukan beberapa jalur UI yang menelan error setelah aksi pengguna. Feedback diperbaiki untuk kegagalan tandai notifikasi dibaca, kegagalan refresh daftar jadwal/peserta setelah penyimpanan, operasi peserta yang hasilnya belum pasti setelah koneksi putus, dan hasil generate peserta yang sebagian gagal. Versi app, service worker, cache, serta bundle Apps Script juga diselaraskan. Seluruh 73 tes yang tersedia lulus pada checkout berformat LF seperti runner Linux GitHub Actions. Halaman publik dan formulir masuk produksi juga berhasil dimuat di browser; pada viewport 664 px tidak ada overflow horizontal dan tidak muncul pesan console warning/error.

Aplikasi memiliki perlindungan yang cukup baik pada source untuk otorisasi berdasarkan role dan kepemilikan, validasi upload, sesi, batas ukuran file, penguncian perubahan bersamaan, pemulihan sebagian transaksi, retry notifikasi idempoten, serta pesan kegagalan yang dapat dipahami pengguna. Perubahan runtime audit ini terbatas pada feedback UI; alur backend dan kontrak API tidak diubah.

Status audit: **source siap untuk uji integrasi terkontrol; belum cukup bukti untuk menyatakan semua alur produksi telah tervalidasi.**

## Cakupan pemeriksaan

- Meninjau PWA, HTML, CSS, bridge transport, service worker, dan formulir login.
- Memeriksa backend Apps Script untuk autentikasi, sesi, role, kepemilikan data, pendaftaran, dokumen, pembayaran, seleksi, daftar ulang, dan pemulihan transaksi.
- Menjalankan semua 73 file tes regresi yang tersedia pada commit terbaru di `main`.
- Menambahkan tes regresi untuk memastikan kegagalan UI mutation dan refresh terlihat oleh pengguna.
- Membandingkan tampilan publik dan login pada situs produksi.
- Memeriksa kesiapan integrasi dan keterbatasan deploy di dokumentasi repo.

## Perbaikan audit

Tiga tes regresi memiliki ekspektasi lama yang tidak lagi sesuai dengan kode:

1. Tes upload mengharapkan ukuran file asli dikirim, padahal PWA dapat mengompres foto dan mengirim ukuran payload hasil olahan bersama Base64-nya.
2. Tes pemulihan pembayaran mencari pesan error lama, sementara source sudah memakai pesan yang lebih spesifik.
3. Tes konfigurasi PWA mengunci nama cache pada versi lama, sehingga gagal setiap kali namespace cache dinaikkan.

Ekspektasi tes diperbarui agar memeriksa perilaku terkini tanpa mengunci nomor versi tertentu; pembaruan tes tersebut tidak mengubah runtime aplikasi.

### Perbaikan feedback UI

- Tandai notifikasi sebagai dibaca sekarang menampilkan pesan jika backend menolak atau koneksi gagal, bukan diam tanpa respons.
- Generate peserta seleksi memakai status peringatan saat sebagian peserta gagal.
- Renderer seleksi kini mengembalikan status berhasil/gagal; jadwal dan peserta yang berhasil disimpan mendapat peringatan jelas bila refresh gagal.
- Pesan saat koneksi putus pada aksi mutasi menjelaskan bahwa status penyimpanan belum pasti dan daftar perlu diperiksa sebelum pengguna mencoba ulang.
- Perbaikan diterapkan pada PWA dan UI Apps Script agar perilaku kedua antarmuka tetap selaras.
- URL app.js, service worker, namespace cache PWA, dan URL bundle Apps Script dinaikkan agar perangkat meminta asset yang telah diperbarui.
- Tes baru menjaga perilaku feedback tersebut tetap tercakup di GitHub Actions.

## Risiko dan tindak lanjut

### Sebelum menyatakan siap produksi

1. Jalankan uji end-to-end pada salinan project Apps Script, Spreadsheet, dan Drive. Uji login/logout, sesi kedaluwarsa, setiap role, pendaftaran, upload dokumen, pembayaran, verifikasi, hasil seleksi, pengumuman, dan daftar ulang.
2. Uji kegagalan parsial dan permintaan bersamaan: penulisan Drive berhasil tetapi Sheet gagal, dua verifikasi pembayaran, dua pendaftaran dengan identitas yang sama, dan timeout lock.
3. Ukur latency login dan validasi sesi dengan jumlah akun serta sesi realistis. Validasi sesi saat ini membaca sheet sesi dan pengguna secara langsung agar pencabutan akses cepat berlaku; beban bacanya perlu diukur terhadap kuota dan ukuran data.
4. Pastikan source kelima file runtime Apps Script sama dengan commit kandidat sebelum menyalin atau memperbarui deployment. GitHub Pages dan Apps Script dirilis terpisah.
5. Uji tampilan halaman dalam desktop lebar, Android/iOS, serta kondisi jaringan lambat dan offline. Pemeriksaan browser audit ini hanya mencakup beranda publik dan layar login pada satu viewport.
6. Putuskan kebijakan verifikasi kepemilikan email/nomor telepon pada pendaftaran Wali sebelum mengandalkan kanal itu untuk pemulihan akun.

### Batas audit

- Tes repo adalah pemeriksaan source dan kontrak; tes tersebut tidak menjalankan runtime Google Apps Script.
- Audit ini tidak memakai akun pengguna, tidak mengakses data pendaftar, dan tidak melakukan perubahan pada Spreadsheet, Drive, Script Properties, atau deployment.
- Pemeriksaan visual produksi tidak mencakup halaman setelah login atau setiap ukuran perangkat.
- Perubahan GitHub tidak otomatis memperbarui backend Apps Script produksi.
- Perbaikan feedback UI pada checkout belum diterbitkan ke GitHub Pages; pemeriksaan visual situs produksi mendahului perubahan lokal tersebut.
